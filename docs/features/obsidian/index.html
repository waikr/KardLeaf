Obsidian 兼容与开放 Markdown 工作流

KardLeaf 把普通 Markdown/TXT、文件夹层级、标签、YAML 属性和 [[双向链接]] 作为核心数据，因此可以作为 Obsidian 笔记库的 Android 端补充，也能与 VS Code、Typora 等工具共享文件。

为什么能和 Obsidian 共用文件

KardLeaf 的正文保存为真实 .md / .txt，而不是只有应用数据库才能解码的记录。Room 数据库主要承担索引、缓存和状态，因此文件本身仍是主要内容载体。

  • 电脑端可以继续使用 Obsidian 打开笔记库目录。
  • VS Code、Typora 或其他文本编辑器也能直接修改同一 Markdown。
  • KardLeaf 可在外部文件变化后刷新自己的索引。
  • 迁移时可以直接复制目录，不要求先导出成专有格式。

目录、标签与 YAML 属性

  • 目录结构：多级文件夹是真实目录层级，适合保持 Obsidian Vault 原有组织方式。
  • #标签：笔记索引会读取标签用于筛选。
  • YAML / Front Matter：属性会被解析，标签等字段进入索引；编辑器属性面板也能显示 Front Matter。
  • 不强制重写正文：数据库索引服务于 App 界面，不意味着必须把 Markdown 改造成数据库专有结构。

[[双向链接]] 与关系图

CodeMirror 扩展包含 Wikilink 点击和显示逻辑，关系图页面也明确读取 [[双向链接]] 建立笔记间的边。

  • 显示状态下 Wikilink 可以作为可点击链接打开。
  • 进入编辑/reveal 状态后仍可修改原始链接文本。
  • 链接索引可进一步用于笔记关系图，观察知识之间的连接。

图片路径兼容

图片引用最容易在跨工具移动时出问题，因此 KardLeaf 提供根目录和相对路径两种模式。

  • ROOT：按笔记库根目录组织图片引用。
  • RELATIVE：使用相对笔记位置的 Markdown 图片引用。
  • 当前目录 / 固定图片目录：相对模式下还可以决定图片实际放置位置。
  • 移动笔记：仓库代码包含移动文件时重写相对图片引用的处理。

多端同步怎么搭配

由于两边看到的是同一套文件，所以同步方案可以自由选择。

  • Syncthing：让电脑和 Android 之间同步整个 Vault 文件夹。
  • WebDAV：使用 KardLeaf 内置 WebDAV 同步管理器。
  • S3：连接兼容 S3 API 的对象存储。
  • 手动复制：也可以直接复制文件夹做离线迁移或备份。

兼容边界

KardLeaf 不是 Obsidian 官方客户端，也不承诺实现 Obsidian 的全部插件生态或所有私有扩展语法。兼容重点是普通 Markdown 文件、目录、标签、YAML 属性、常用链接与开放文件工作流。

因此更准确的定位是：KardLeaf 可以作为本地 Markdown / Obsidian 工作流的 Android 补充，而不是在手机上完整复制 Obsidian 桌面版。

继续了解

本地文件管理查看文件夹、标签和真实文件。同步与备份选择 WebDAV、S3 或文件夹同步。Markdown 编辑器了解扩展语法和 Wikilink。
