WebDAV、S3 同步与自动备份

KardLeaf 提供应用内 WebDAV 与 S3 兼容同步，并保留 Syncthing 这类文件夹同步工作流；同时支持同步预览、远端检查、JSON 导入导出和定期自动备份。

WebDAV 云同步

项目包含独立 WebDavCloudSyncManager，设置页把 WebDAV 和 S3 放在“云同步”同一级标签页中，而不是仅提供一个外部链接。

  • 账号/端点设置：保存 WebDAV 连接信息后由同步管理器访问远端。
  • 同步预览：设置搜索中有“同步预览”，用于先查看计划中的文件变化。
  • 远端检查：提供测试远端检查入口，便于在真正同步前确认远端状态。
  • 实时同步选项：偏好设置包含实时同步相关状态，可控制更主动的同步行为。

S3 兼容对象存储同步

S3 模块拥有独立客户端、签名、凭据保存、设置页和同步管理器。它面向兼容 S3 API 的对象存储，不局限于某一家云厂商。

  • 端点与 Bucket：设置中保存对象存储地址、桶、前缀和凭据。
  • 连接测试：设置页可以只读测试连接并统计发现的文件。
  • 同步计划：先生成本地/远端差异计划，再决定如何处理。
  • 冲突选择：界面会显示本地、远端是否存在，并允许为项目选择处理方式或跳过。
  • 大文件：设置说明写明单文件采用流式传输，最大 5 GiB。
  • 恢复副本：管理器代码维护远端恢复副本目录，在异常处理时保留恢复路径。

与 Syncthing / 普通文件同步协作

因为正文是普通文件夹中的 Markdown/TXT，KardLeaf 也可以不使用应用内云同步，而把整个笔记库交给 Syncthing、网盘目录或手动复制。

  • KardLeaf 负责读取/索引本地文件，外部工具负责搬运文件。
  • 其他端使用 Obsidian、VS Code、Typora 等工具时仍能直接读取同一批 Markdown。
  • 这种方式的核心是“文件夹同步”，不是依赖 KardLeaf 专有数据库协议。

数据导入、导出与自动备份

  • JSON 导出：设置页提供用户数据导出回调，把应用相关数据打包保存。
  • JSON 导入：可从导出的数据恢复应用记录。
  • 自动备份目录：用户可以选择备份目标目录。
  • 备份周期：偏好设置记录自动备份周期，MainActivity 会根据上次备份时间决定是否再次写出备份。
  • 笔记正文独立：即使不依赖 JSON 备份，真实 Markdown/TXT 文件本身仍可直接复制保存。

同步时的数据保护思路

同步涉及两个可同时变化的数据源，因此代码中专门有文件互斥、同步计划和冲突选择。S3 设置页面也明确提醒兼容服务对条件写入的支持可能不同，应避免两端同时修改同一文件。

如果同时在电脑和手机改同一 Markdown，任何文件同步方案都可能产生冲突。比较稳妥的方式是先完成一端同步，再在另一端继续编辑。
