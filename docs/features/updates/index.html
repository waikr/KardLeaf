版本更新检查与发布信息

KardLeaf 内置 GitHub Releases 更新检查逻辑，可以自动或手动查询最新版本、解析版本号与发布说明，并在检测到新版本时给出应用内更新提示。

更新信息来源

AppUpdateChecker 直接读取 KardLeaf GitHub 仓库的 latest release API：

https://api.github.com/repos/waikr/KardLeaf/releases/latest

这样应用与项目正式 Release 保持同一发布源，不需要另外维护一套版本列表。

版本比较

检查器会读取当前应用版本和 latest release 的 tag/name 信息，判断是“已有新版本”还是“已经最新”。

  • UpdateAvailable：返回完整 release 信息，用于显示更新对话框。
  • UpToDate：记录最新 tag，表示无需更新。
  • Failed：网络或解析失败时给出错误消息，而不是把失败误判成没有新版本。

自动检查

MainActivity 中存在自动检查流程，并记录当天是否已尝试检查，避免每次进入应用都无休止请求 GitHub API。

  • 满足自动检查条件时发起后台请求。
  • 发现新版本后显示更新对话框。
  • 没有更新时只记录状态，不强制打扰用户。

设置页手动检查

设置页同样调用 AppUpdateChecker.checkLatestRelease()，用户可以主动检查更新，而不需要等待自动触发。

  • 检查过程中有 loading 状态。
  • 完成后显示当前更新检查结果。
  • 发布说明读取长度设有上限，避免异常超长 Release Notes 影响界面。

官网与 APK 下载保持一致

官网首页也会读取 Releases 信息，并优先向用户展示最新 APK 下载状态。这样应用内检查、GitHub Release 和官网下载安装入口可以围绕同一版本发布流程工作。

继续了解

设置与自定义手动检查更新位于设置体系。备份更新前可先备份重要数据。本地文件正文是普通 Markdown，升级不改变其开放格式。
