AI 写作助手

KardLeaf 已在代码中加入 AI 文本助手，可对选中文本或笔记执行摘要、润色、扩写、续写、缩短、纠错、翻译、解释、提取要点/待办、生成标题和自定义指令，并支持 OpenAI 兼容接口、New API 与试用模式。

12 类 AI 文本操作

操作用途
AI 摘要提炼关键事实、结论与必要背景。
AI 润色改善表达、逻辑和可读性，同时要求不改变原意。
AI 扩写在不虚构事实的前提下补充解释、过渡和细节。
AI 续写沿用原文语言和上下文继续写作。
缩短内容删除重复与冗余表达，保留核心信息。
纠错与语病修复修复错别字、标点、语法和语病。
翻译中文默认译为英文，其他文本默认译为简体中文。
解释内容解释概念、逻辑和结论。
提取要点输出去重后的 Markdown 要点列表。
提取待办把可行动事项整理成 Markdown 任务列表。
生成标题根据正文生成简洁笔记标题。
自定义指令由用户自行描述希望 AI 如何处理文本。

模型与 API 接入方式

KardLeafAiProvider 当前定义三种 Provider。

  • OpenAI 兼容：填写 Base URL、模型名称和可选 API Key，请求发送到 Chat Completions 兼容接口。
  • New API：自动处理常见 /v1/chat/completions 路径拼接。
  • 试用：使用构建时配置的 KardLeaf Trial Gateway，不要求用户自己测试连接。
  • 连接测试：自定义 API 可以在设置中发起测试请求，确认地址与模型可用。

API Key 本地保护

用户自己的 API Key 不以明文直接写入普通 SharedPreferences。代码使用 Android Keystore 创建 AES 密钥，通过 AES/GCM/NoPadding 加密后再保存 IV + 密文。

这描述的是客户端存储实现；当用户调用自己配置的第三方 AI 服务时，请求正文和授权信息仍需要发送到该服务端点，数据处理规则取决于用户选择的服务商。

长文本分段处理

AI 客户端对输入长度做了明确限制，以防一次请求无限扩大。

  • 直接请求：最多 24,000 字符。
  • 可分段动作：摘要、提取要点、提取待办、生成标题支持更长内容分段处理。
  • 最大分段输入：当前代码限制为 300,000 字符。
  • 分段大小：每段约 18,000 字符，先分别处理，再进行二次合并。
  • 其他操作：润色、扩写等不支持超长自动分段时，会提示缩小选区。

对 AI 结果继续修改

除了第一次生成，客户端还提供 revise()：把原始文本、当前 AI 结果和用户补充要求一起发送，再生成修改后的完整结果。

  • 可以在第一次摘要后要求“更短一些”。
  • 可以在润色后补充“保持更口语化”。
  • 修改提示要求尽量保留原始事实和 Markdown 结构。
  • 正在进行的网络请求可以主动取消。

网络与错误处理

  • 连接超时 30 秒、读取超时 120 秒、写入超时 60 秒。
  • 试用网关会把限流、服务繁忙、输入过长、上游超时等错误转换成可读提示。
  • 自定义服务会解析标准 error.message，并限制错误文本长度。
  • AI 返回内容兼容常见 choices[].message.content 以及部分 text 形式。
