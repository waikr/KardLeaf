搜索、日期视图与笔记统计

KardLeaf 的搜索支持标题、正文、大小写、正则、标签和文件夹条件，并结合搜索片段跳转、日期视图、历史搜索、属性统计与侧边栏热力图。

全局搜索条件

搜索数据模型 NoteSearchOptions 把搜索范围和筛选条件明确拆开，因此可以组合使用，而不是只做简单的标题包含。

条件说明
matchCase区分大小写。
useRegex使用正则表达式匹配。
matchTitle是否在笔记标题中匹配。
matchContent是否在正文中匹配。
tag把结果限制到指定标签。
folder把结果限制到指定文件夹。

搜索结果与定位

  • 结果片段：搜索结果模型包含 snippet 与 matchedText，可显示命中附近正文。
  • 命中范围：结果携带 startOffset，首页卡片在存在有效偏移时可以提供搜索跳转。
  • 标题与正文独立：可以只查标题、只查正文，或同时搜索。
  • 元数据筛选：tag/folder 与文本查询可以组合，适合缩小大型笔记库范围。
  • 特殊字符处理：仓库包含专门搜索用例，覆盖换行、反斜杠、UTF-16/emoji、大小写等场景。

历史版本搜索

历史版本不是只能按时间翻。NoteHistoryStore 提供历史内容搜索预览，会对查询做安全处理并返回历史版本摘要。当前实现把单次历史搜索结果限制在 100 条，避免一次加载过多旧正文。

  • 在历史版本列表内输入关键词筛选旧版本。
  • 选择两个版本进行比较，显示变更。
  • 恢复选中的历史版本到当前笔记。
  • 历史保留数量可配置，并提供超限清理预览。

按日期浏览笔记

日期页把普通列表换成时间维度。当前实现可以按今天、周、月选择范围，并以笔记最后修改时间进行归组和排序。

  • 今天：聚焦当前日期的笔记。
  • 本周：按周范围汇总。
  • 月份：支持可见月份切换、月份选择器与手势切换。
  • 时间排序：选中日期范围内的笔记按最后修改时间降序组织。

单篇笔记文字统计

属性面板调用专门的 NoteTextStats 统计器，默认会考虑跳过 Front Matter，避免 YAML 元数据污染正文统计。

  • 字符数：统计正文字符量。
  • 词数（含标点）：用于快速估算内容规模。
  • 词数（不含标点）：提供另一种文本量口径。
  • 行数：适合代码、列表和长文结构统计。
  • 段落数：按正文结构统计段落。
  • 笔记库总字符数：仓库层还会异步汇总整个笔记库的字符总量。

侧边栏热力图

侧边栏存在独立热力图组件与按天统计逻辑。代码为热力图维护每日数据、颜色深度和统计缓存，并在用户空闲后刷新较重的笔记库统计。

热力图用于观察一段时间内的记录活动；具体指标和展示样式会继续随版本调整，因此这里以当前代码结构为准，不把它描述成固定不变的算法。
