附件、音频与视频预览

除了图片，KardLeaf 的预览链路还支持本地音频、视频和普通附件引用；媒体通过独立资源响应与 Range 请求流式读取，避免把大文件整体塞进 JavaScript 或内存。

附件类型

编辑器工具栏已经包含 Attachment 插入入口，而预览层会把可解析的附件资源交给专门的媒体处理逻辑。

  • 图片：继续按图片资源加载和预览。
  • 音频：MIME 以 audio/ 开头时，预览使用原生 HTML audio 控件。
  • 视频：MIME 以 video/ 开头时，预览使用 video 控件。
  • 普通文件：不能直接媒体播放的附件仍保留链接形式，可交给系统或对应应用打开。

本地媒体流式读取

PreviewAttachmentResponse 专门处理预览中的本地媒体请求。代码注释明确说明：媒体通过 SAF 资源流读取，不把视频字节塞进 JS Bridge 或一次性堆进内存。

  • Range 请求：支持浏览器媒体控件常用的分段读取。
  • 大文件更友好：播放器可以按需要读取部分内容，而不是启动时加载完整视频。
  • MIME 校验：只有音频/视频类型进入媒体响应路径。
  • 资源签名：本地预览 URL 包含版本和签名参数，避免任意路径直接被 WebView 读取。

Markdown Preview 中的播放

preview-media.js 会扫描渲染后的附件链接并判断媒体类型，随后创建浏览器原生媒体元素。

  • 视频自动限制为容器宽度，并设置最大显示高度。
  • 音频使用完整宽度的原生控制条。
  • 加载失败时显示状态提示，并保留下方附件链接作为兜底。
  • 远程视频链接也有常见扩展名到 MIME 的映射逻辑。

预览安全处理

媒体预览不是把笔记里的原始 HTML 无限制执行。预览链路同时有 HTML sanitizer，并对危险链接进行过滤。

本页描述的是 KardLeaf 当前媒体预览实现。旧 Quillpad 兼容目录中也保留部分附件模型或占位代码，但这里重点只介绍 KardLeaf 实际 Preview 路径中可确认的能力。
