归档、废弃与自动清理

KardLeaf 把归档和废弃分成两个状态：归档用于暂时从日常视图中移开但继续保留，废弃用于进入 Trash 流程；同时支持恢复、清空废弃和按天数自动清理。

归档和废弃不是一回事

笔记模型同时保存 isArchived 与 isTrashed，数据库也为活动、归档和废弃查询建立独立索引。

状态用途
归档内容仍保留在笔记库中，但从常用工作区分离，适合已结束项目或暂不需要的资料。
废弃进入 Trash 状态并记录 deletedAt，等待恢复或真正清理。

归档与恢复

  • 单篇切换：编辑器桥接层可以根据当前状态执行 archiveNote 或 restoreNote。
  • 侧边栏入口：Archive 是独立 Drawer Item。
  • 批量操作：长按选择栏包含 Archive，可一次处理多篇笔记。
  • 任务扫描隔离：Markdown 任务查询会排除已归档笔记，避免旧项目任务继续出现在活动任务列表。

废弃、恢复与彻底删除

  • 废弃视图：Trash 是独立筛选页。
  • 删除时间：模型保存 deletedAt，便于自动清理判断。
  • 清空废弃：Dashboard 提供确认对话框，随后调用 repository.emptyTrash() 真正清理废弃内容。
  • 恢复：废弃内容保留状态直到恢复或清空，不等同于第一次点击删除就立即永久消失。

按天数自动清理

仓库接口包含 cleanupExpiredTrash(olderThanDays)，设置中也保存 trashAutoCleanDays。这意味着用户可以指定废弃内容保留多久，再自动执行过期清理。

自动清理属于不可逆数据操作，实际使用时建议同时保留 Markdown 文件备份或同步副本。

任务也有自己的废弃区

任务系统单独维护 isTrashed，任务页也有清空任务废弃的逻辑。笔记 Trash 与任务 Trash 是两套数据状态，不会因为清理其中一个就自动等同处理另一个。
